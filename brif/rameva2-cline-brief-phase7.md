## Сессия и CSRF

1. Один `SessionService` — единственное место, где вызывается `session_start()`. Параметры: `use_strict_mode=1`, cookie `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, каталог — `storage/sessions`. Вызовы `session_start()` в других местах убрать.
2. Один ключ токена в сессии, одно имя поля формы — `_csrf`. Один генератор, один проверяющий. Альтернативные ключи и запасные варианты проверки не допускаются.
3. Токен — `random_bytes(32)` в hex. Сравнение через `hash_equals`. Пустой токен с любой стороны — отказ.
4. Плейсхолдер `{{ form_fields:ID }}` для `page.html` и layout: выводит скрытое поле `_csrf`, скрытое поле honeypot и записывает в сессию время показа формы с данным ID. Пользователь или агент больше ничего скрытого в форму не добавляет.
5. Имя поля honeypot не из словаря (не `website`, не `url`): вычисляется из ключа установки и ID формы, стабильно для установки. Поле скрыто CSS, `tabindex="-1"`, `autocomplete="off"`.
6. Страница, на которой использован `{{ form_fields:... }}`, отдаётся с `Cache-Control: private, no-store`.
7. Время заполнения проверяется только по времени, записанному на сервере при показе формы. Поле `submit_time` из формы убрать, клиентскому значению не доверять. Минимальное время заполнения (по умолчанию 3 секунды) и максимальный возраст формы (по умолчанию 2 часа) — в конфигурации.
8. Для POST-запросов формы: если есть заголовок `Origin`, его хост должен совпадать с хостом сайта; если `Origin` нет, но есть `Referer` — проверять его; несовпадение — отказ.

## Конечная точка

1. Системный маршрут `POST /form/{form_id}`. Обрабатывается в Kernel после чёрного списка и общего rate limiter, до роутера. Не входит в белый список `pages/`, на него не действуют суффикс и канонический редирект. В sitemap и llms.txt не попадает.
2. Канонический редирект применяется только к GET и HEAD. POST не редиректить никогда.
3. GET на этот маршрут отдаёт обычную страницу 404.
4. Формат ответа — JSON `{success, message, errors}`. Коды: `200` успех; `422` ошибки валидации с `errors` по полям; `403` CSRF или Origin; `429` лимиты, с заголовком `Retry-After`; `500` сбой отправки, в сообщении клиенту — только общий текст, детали — в лог.
5. Срабатывание honeypot: ответ `200` с `success: true`, письмо не отправляется, событие пишется в `storage/logs/security.log`.
6. Запрос считается в rate limiter один раз.

## MailService

1. Заменить заглушку `checkRateLimits()` (сейчас `return true`) реальной проверкой: `min_interval`, `ip_limit`, `hourly_limit`, `daily_limit` из `app/Config/Mail.php`. Чтение-изменение-запись счётчиков в `storage/cache` под `flock`. Проверка лимитов — один раз, в `send()`, не в конструкторе.
2. Единая функция определения IP клиента (`Request::ip()` или аналог): по умолчанию `REMOTE_ADDR`; `X-Forwarded-For` и `CF-Connecting-IP` учитывать только если `REMOTE_ADDR` входит в список `trusted_proxies` из конфигурации. Использовать её в RateLimiter, MailService, логах.
3. Транспорты: `smtp` (основной), `mail()` (запасной), `sendmail`. Для `sendmail` — `proc_open` с массивом аргументов и передачей письма через stdin; без shell-строки, без `echo "..." |`, без `addslashes`.
4. SMTP-клиент: сначала проверить, как отправка по SMTP реализована сейчас в `system/Services/MailService.php`. Недостающее доработать, ориентируясь на исправленный клиент из wwbridge.loc, без копирования его целиком. До включения в продакшен проверить AUTH (LOGIN и PLAIN), STARTTLS и SSL (порт 465) против реального SMTP-сервера, не только Mailpit. Проверка сертификата включена по умолчанию; отключается только флагом конфигурации для локального режима. Таймауты соединения и чтения (10 и 15 секунд). Dot-stuffing, нормализация CRLF. Причина сбоя — в лог, не клиенту.
5. Заголовки: убрать `X-Mailer`. В заголовках и тексте письма не упоминать имя фреймворка. `From` — адрес сайта из конфигурации, не адрес посетителя; `Reply-To` — очищенный адрес посетителя. Обязательны `Date`, `Message-ID` на домене сайта, `MIME-Version`. Письмо — `multipart/alternative` (text/plain и text/html). Все значения в HTML-части экранировать.
6. Шаблоны писем: `system/Mail/*.html` по умолчанию, `app/Mail/*.html` — переопределение (тот же приоритет, что у `app/Pages` и `app/Layouts`). Плейсхолдеры `{{ }}`, значения экранируются.
7. События: `mail.sent` оставить, добавить `mail.failed`.
8. Лог — `storage/logs/mail.log`: домен получателя, статус, код ошибки; без тела письма.

1. `pages/contact.html` и `app/Config/Forms.php` с формой `contact`: поля name, email, phone, message; в разметке — `{{ form_fields:contact }}`.
2. `assets/js/forms.js`: отправка через `fetch` на `/form/contact`; успех показывается только при `success === true`; иначе выводятся сообщение и ошибки по полям из ответа. Без inline-скриптов в странице.

## Тесты

Создать `tests/forms_smoke.php` — CLI-скрипт, который остаётся в репозитории. Параметры: `BASE_URL`, необязательный `MAILPIT_URL` (при наличии проверяет письма через API Mailpit). Проверки:
- корректная отправка → `200`, письмо получено;
- нет токена → `403`; неверный токен → `403`; токен из другой сессии → `403`;
- отправка быстрее минимального времени → отказ;
- `submit_time` из запроса не влияет на результат;
- заполненный honeypot → `200`, письма нет, запись в `security.log`;
- превышение лимитов → `429` и снятие блокировки по истечении времени;
- POST по адресу с нестандартным регистром или суффиксом не получает `301`;
- CR/LF в полях name и email не добавляют заголовков в письмо;
- слишком длинное сообщение → `422`;
- запрос с чужим `Origin` → `403`.
