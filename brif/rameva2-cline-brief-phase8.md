## Часть B: приём готовых страниц от ИИ

Исходные данные: пользователь или агент кладёт в `pages/` готовые `.html` и в `assets/` готовые `css`, `js`, `images`, `fonts` как их сгенерировал ИИ — с относительными путями и собственными тегами `<title>`, `<meta>`, `<link rel="canonical">`. Страница должна работать без правок.

### B1. Нормализация ссылок и путей к ассетам

1. Новый класс в `system/Rendering/`. Работает с текстом страницы и layout до подстановки плейсхолдеров. Однопроходный сканер тегов, не DOMDocument и не регулярное выражение по всему тексту. Правит только значения атрибутов `href`, `src`, `srcset`, `poster`, `data-src` и `url()` в `style="..."` и в блоках `<style>`. Не трогает: тела `<script>`, HTML-комментарии, текст внутри `<pre>` и `<code>`, значения с `{{`. Если в документе есть `<base>`, нормализацию пропустить. Результат идемпотентен.
2. Карта ассетов — список файлов `assets/` в PHP-файле `storage/cache/assets.php` под Guard. Строится вместе с картой маршрутов и обновляется по тому же условию; в условие добавить каталог `assets/`.
3. Относительный путь (не начинается с `/`, `#`, `?`, не содержит схемы, не `data:`, `mailto:`, `tel:`, `javascript:`): убрать ведущие `./`, `../`, префикс `assets/`; если `assets/<путь>` есть в карте ассетов — заменить на `/assets/<путь>`. Строка запроса и фрагмент сохраняются. Если файла нет в карте — значение не менять, запись в debug-лог.
4. Внутренние ссылки в `href` тега `<a>`: убрать ведущие `./`, `../`, `/`; убрать расширение `.html`, `.htm`, `.php` и настроенный суффикс; `index` и завершающий `/` означают каталог. Если логический путь есть в карте маршрутов — заменить на канонический адрес, построенный тем же методом, что использует роутер (без второй реализации логики суффикса). Нет в карте — не менять. Фрагмент и строка запроса сохраняются.
5. Время нормализации страницы около 50 КБ измерить и привести в отчёте. Кэширования результата на этом этапе не делать.
6. Тест `tests/normalizer_test.php` (CLI, функция без HTTP), с картой ассетов `css/style.css`, `js/app.js`, `images/logo.svg`, `images/a.png`, `images/b.png`, `fonts/a.woff2` и картой маршрутов `/`, `/about`, `/contact`, `/company`, `/company/info`. Обязательные случаи:
   - `css/style.css`, `./css/style.css`, `assets/css/style.css`, `../assets/css/style.css` → `/assets/css/style.css`;
   - `images/logo.svg?v=2` → `/assets/images/logo.svg?v=2`;
   - `srcset="images/a.png 1x, images/b.png 2x"` — оба значения заменены;
   - `url(images/a.png)` в `style="..."` и `url('fonts/a.woff2')` в `<style>` заменены;
   - без изменений: `/css/style.css`, `https://cdn.example/x.css`, `//cdn.example/x.js`, `data:...`, `#top`, `mailto:...`, `tel:...`, `javascript:...`, значение с `{{`, несуществующий `images/none.png`, содержимое `<script>`, комментарии, `<pre>`;
   - ссылки: `index.html` → `/`; `about.html` → `/about`; `./about.html#team` → `/about#team`; `../about.html` → `/about`; `company/info.html` → `/company/info`; `company/index.html` и `company/` → `/company`; `/about.html` → `/about`; `missing.html` без изменений;
   - при суффиксе `.html`: `about.html` → `/about.html`, `index.html` → `/`, `company/index.html` → `/company.html`;
   - при наличии `<base>` вход возвращается без изменений;
   - повторный прогон результата не меняет его.

### B2. Собственные метаданные страницы без дублей

1. Если страница — полный HTML-документ, из её `<head>` собрать как входные данные для SeoService: `<title>`, `<meta name="description">`, теги `og:*` и `twitter:*`. Приоритет: данные контроллера, затем собственные теги страницы, затем сгенерированные значения по умолчанию (`<h1>`, начало текста, конфигурация).
2. В выводе удалить собственные `<title>`, `<meta name="description">`, `<link rel="canonical">`, `<meta property="og:*">`, `<meta name="twitter:*">` страницы — остаются только сгенерированные движком. Правило действует и при странице без layout, и при странице с layout.
3. `<script type="application/ld+json">` страницы не трогать. SeoService не добавляет JSON-LD того же верхнеуровневого `@type`, что уже есть в странице.
4. Тест `tests/seo_dedupe_test.php` (CLI): страница со своими `<title>`, description, canonical, og:title, twitter:title — в результате по одному каждого элемента, значения берутся из страницы, если контроллер их не задал; контроллер перекрывает значения страницы; JSON-LD страницы сохранён.
5. Живая проверка: на `/about` и `/contact` в выводе ровно один `<title>`, один `<link rel="canonical">`, один `og:title`.
