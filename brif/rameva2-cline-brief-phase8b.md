# Rameva 2 — техническое задание, этап 8B: подтверждение недоказанного и проверочные утилиты

## Правила отчёта (действуют с этого этапа)

1. Каждое «PASS» сопровождается выводом команды или фрагментом реального результата. Ссылка на код подтверждением не считается.
2. Если критерий выполнен не полностью — «НЕ ВЫПОЛНЕНО» с причиной. Расхождение между таблицей результатов и разделом ограничений недопустимо.
3. Пропущенные проверки (SKIP) считаются невыполненными.
4. Пути в отчёте — относительно `public/`, без префикса `public/`. Если файл лежит вне `public/`, указать это явно.
5. Пункт, помеченный в прошлом отчёте «не требуется», выполнять, если он есть в этом брифе.

## Часть A: закрыть недоказанное

1. **Этап 6.** Показать имена файлов в `storage/` (без содержимого) и код и заголовки ответа `https://fw2.loc/`. Пройти установщик штатным путём, чтобы `installer.key` и `install.lock` создал установщик, а не ручное действие; приложить результаты его проверок окружения. Если до установки сайт отдаёт обычные страницы вместо установщика — записать «блокировка до установки: НЕ ВЫПОЛНЕНО» и исправить по брифу этапа 6. Для каждого пункта раздела «Критерий готовности» брифа этапа 6 дать статус и вывод команды.
2. **Ключ установки.** Выяснить формат `storage/installer.key` и описать его в отчёте. Если это не PHP-файл под Guard — перевести в PHP-файл, возвращающий значение, под Guard (по образцу `storage/integrity.state.php`), старый файл удалить. Чтение ключа — одна функция. Если ключа нет, функция создаёт его (`random_bytes(32)`, атомарная запись под `flock`) и возвращает; установщик использует уже созданный ключ и не перегенерирует его. Из `system/Security/RateLimiter.php` убрать запасной вариант `hash('sha256', $ip)` без ключа. Если ключ получить невозможно (каталог недоступен для записи) — не падать с Fatal, не считать лимит по IP и записать событие в `storage/logs/security.log`.
3. **Tripwire в установленном состоянии.** Выводом команд подтвердить: `action=build` → `built files=N`; `action=check` → `ok`; после тестового изменения файла в `system/` → `mismatch`, после отката снова `ok`; верный ключ → `200`, неверный и отсутствующий → `403` с пустым телом. Проверку прав доступа файлов на Windows не демонстрировать реальными правами: подтвердить логику тестом `tests/tripwire_test.php` на подставном манифесте (расхождение прав — отдельный тип события) и записать «на Linux не проверялось». Проверку посторонних `.php`: создать временный `assets/x.php`, выполнить проверку, показать критическое событие в `storage/logs/integrity.log`, удалить файл.
4. **Почта.** `MAILPIT_URL` — адрес API Mailpit (обычно `http://127.0.0.1:8025`; уточнить у Сергея). Проверить `curl <MAILPIT_URL>/api/v1/messages`. Запустить `tests/forms_smoke.php`, цель — 0 SKIP. Показать полученное в Mailpit письмо для транспорта `smtp` и для `mail()`; если `mail()` не доставил — записать «mail() не доставляет» в отчёт и в текст диагностики.
5. **`ClientIp`.** Создать `tests/clientip_test.php`: цепочка `X-Forwarded-For` с подделанным левым адресом и доверенным прокси справа не меняет IP клиента; недоверенный `REMOTE_ADDR` — заголовки игнорируются; невалидный адрес — результат `REMOTE_ADDR`.
6. **`SessionService`.** Убрать оператор `@` у `session_start()`. Неудачу старта сессии обрабатывать явно: запись в `storage/logs/app.log`, форма отвечает `500` с общим текстом.
7. **Живые проверки.** `curl -s https://fw2.loc/about` и `https://fw2.loc/contact`: показать количество `<title>`, `rel="canonical"`, `og:title` — по одному.
8. **Логи и IP.** Показать список файлов в `storage/` и по одной обезличенной строке из каждого `.log`; указать, где IP хранятся открытым текстом.
9. **`.gitignore`.** Подтвердить `git check-ignore -v`: `storage/index.php` и `storage/.htaccess` не игнорируются; `storage/cache/*`, логи и сгенерированные файлы игнорируются. Если git не инициализирован — написать об этом.

## Часть B: проверочные утилиты

1. **`tests/smtp_live_test.php`** (CLI-only). Читает настройки из `app/Config/Mail.php` и `app/Config/Local.php`, отправляет одно тестовое письмо на адрес из аргумента и выводит по шагам результат: подключение, STARTTLS или SSL, проверка сертификата, AUTH, MAIL FROM, RCPT TO, DATA, ответ сервера. Пароль в выводе маскируется. Код возврата 0 только при успешной отправке.
2. **`tests/server_check.php`** (CLI-only). Внешняя проверка развёрнутого сайта по `BASE_URL`: HTTP-запросы с таймаутом, без следования редиректам, состояние сайта не меняется. По каждому пункту PASS или FAIL, код возврата не 0 при любом FAIL, в конце сводка и список FAIL с адресами. Проверки:
   - `/` → `200`; случайный несуществующий путь → `404`, без упоминаний фреймворка в теле и заголовках;
   - `/system/Boot.php`, `/app/Config/Mail.php`, `/system/Services/MailService.php` → `403` или `404`;
   - `/pages/index.html`, `/app/Layouts/main.html`, `/system/Layouts/default.html` → `403`, `404` или пустое тело;
   - `/storage/logs/app.log`, `/storage/integrity.manifest.php`, `/storage/cache/routes.php` и файл ключа установки (по фактическому имени) → `403`, `404` или пустое тело;
   - `/tests/forms_smoke.php` → не `200` с содержимым;
   - `/.env`, `/.git/HEAD`, `/composer.json` → `403`, `404` или пустое тело;
   - `/wp-login.php`, `/xmlrpc.php` → `403`; `/cron.php` без ключа → `403` с пустым телом;
   - `/robots.txt`, `/sitemap.xml`, `/llms.txt` → `200`; `/favicon.ico` → `200`, если файл существует, иначе пометка «файла нет»;
   - `GET /form/contact` → `404`;
   - ответ `/contact`: `Set-Cookie` с `HttpOnly` и `SameSite`, `Cache-Control` содержит `no-store`;
   - во всех полученных ответах нет `X-Powered-By` с версией PHP и нет имени фреймворка в заголовках.
   Выполнить против `fw2.loc`, результат приложить к отчёту.

## Правила работы

Структурные решения не принимать самостоятельно — спрашивать. Существующее дорабатывать точечно, старые проекты — только ориентир. Все новые скрипты — CLI-only: первой исполняемой строкой выход с `404` при `PHP_SAPI !== 'cli'`.

## Критерий готовности

Для каждого пункта части A в отчёте вывод команды. `tests/forms_smoke.php` проходит без SKIP. Tripwire проверен в установленном состоянии. Ключ установки хранится в PHP-файле под Guard, запасного хэширования IP без ключа нет. `tests/server_check.php` и `tests/smtp_live_test.php` созданы, `server_check.php` выполнен против `fw2.loc`, результат приложен.
