# Rameva 2 — бриф этапа 8F

Пути — относительно `public/`. Каждый изменённый PHP-файл — `php -l`, вывод в отчёт дословно.

## A. `Router::sourceSignature()` — не на каждый запрос

Сейчас конструктор `Router` на каждый HTTP-запрос обходит все файлы в `pages/`, `assets/`, `app/Config/`, чтобы сравнить подпись источника с сохранённой. Для `assets/` с большим числом файлов (иконки, библиотеки) это дорого при каждом визите.

**A1.** В `app/Config/App.php` новый параметр `route_check_interval` (секунды). Значение по умолчанию: `0`, если `debug=true`; `60`, если `debug=false`.

**A2.** В `Router`: метка времени последней проверки подписи — отдельный файл под Guard, например `storage/cache/.route_check_at`. Если `route_check_interval > 0` и с последней проверки прошло меньше интервала — подпись не считается, карта маршрутов берётся из уже загруженного кэша без сравнения (если кэш-файл существует; если его нет — подпись всё равно считается, иначе сайт не запустится на пустом кэше).

**A3.** Если `route_check_interval === 0` — поведение как сейчас, без изменений (нужно для `debug=true`, когда любое изменение должно подхватываться немедленно).

**A4.** Обновить метку времени после каждого реального вычисления подписи (а не только при найденном расхождении).

Проверка: при `route_check_interval=60` — изменить файл в `pages/`, сразу запросить любую страницу (карта не должна обновиться), подождать 60+ секунд или вручную состарить метку, запросить снова (карта должна обновиться). Привести оба результата.

## B. Две мелкие правки без отдельной логики

**B1.** `blacklist.patterns` в `Security.php` НЕ менять — записи `phpmyadmin` и `pma` там нужны намеренно. На ISPmanager (и аналогичных панелях) `домен/phpmyadmin/` штатно обслуживается отдельным `location`/`Alias` на уровне Nginx/Apache в обход PHP фреймворка — легитимный администратор никогда не доходит до этой проверки. Если запрос всё же сюда попал, это либо сайт без настроенного алиаса (реального phpMyAdmin там и нет), либо сканер — 403 уместен в обоих случаях.

Вместо этого — убрать `/phpmyadmin/` только из `system/Security/Honeypot.php` (`$wpProbePaths`): этот путь всё равно перехватывается чёрным списком раньше (шаг 1 против шага 3 в `Kernel::launch()`), поэтому строка в `Honeypot` недостижима и ничего не защищает — просто мёртвый код. Это не ослабляет защиту: блокировка остаётся, только в `blacklist`, а не задвоена в `Honeypot`.

Добавить в `Security.php` рядом с `phpmyadmin`/`pma` в `blacklist.patterns` комментарий:
```
// 'phpmyadmin' и 'pma' НЕ убирать: на ISPmanager и аналогичных панелях
// домен/phpmyadmin/ штатно обслуживается отдельным location/Alias на уровне
// Nginx/Apache в обход PHP — сюда долетает только запрос без настроенного
// алиаса или от сканера, и 403 здесь корректен в обоих случаях.
```

**B2.** Заменить упоминания `token` (как поля конфигурации) на `token_hash` в комментариях: docblock класса `Installer`, docblock `Installer::ensureCronToken()`, хвостовой комментарий `cron.php`. Это только текст комментариев, не код.
